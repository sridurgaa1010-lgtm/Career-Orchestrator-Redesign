## 1. Your mission

You own the **brain** of the product: the calculation code in `engine/` and the catalogue data in `data/v2/`. The engine turns a worker's words into skill suggestions, ranks roles, builds a learning plan, selects motivation messages, checks job adverts and runs the fairness comparison. It is plain Python with no AI model, no network and no database. Your biggest enemy is **an AI assistant inventing things** (skills, courses, numbers). The rules below stop that.

## 4. Hard rules for this role

1. **Inputs the engine may use:** confirmed skill levels (0 to 3), role requirements, interests, hours. **It must never receive or use age, date of birth, graduation year, gender, name, years of experience, education or country.** The CSV column `years_experience` is never read.
2. **Never invent** skills, aliases that are not plain keyword phrases, courses, links, hours, statistics, job adverts, or "recorded AI replies". If data is missing, use `null` and say so.
3. **Everything numeric is provisional** (weights, thresholds, hours per level, importance). Label it so; never present it as validated.
4. **Evidence is verbatim.** A quote shown to a worker must be an exact substring of their own text (`core.quote_is_grounded`). Inferred levels never exceed 2.
5. **Deterministic.** Same input, same output. Ties are broken by role id ascending.
6. **Standard library only** inside `engine/`.
7. **Locked numbers** (section 8) are asserted by tests. If a change moves them, the tests fail: stop, and tell Dev 4. Do not edit tests to make them pass.

## 6. The algorithms (exact)

Constants in `engine/core.py`: `WEIGHTS = {skill_coverage: 0.60, preference_fit: 0.15, learnability: 0.25}`, `H_MAX = 120.0`, `BLOCK_COV = 0.5`. Fairness thresholds `THRESH`: skills_jaccard_min 0.90, top3_overlap_min 3, kendall_tau_min 0.90, max_abs_score_delta_max 0.03, plan_hours_delta_max 10.0, lexicon_hits_max 0.

### 6.1 Skill suggestion (`extract_rules.suggest`)
1. Split each work example into clauses at commas, semicolons, line breaks and the word "and"; keep only clauses that appear exactly in the original text.
2. For every scored skill, test its phrases in `aliases.json` (whole word, case-insensitive, longest first). A hit links the clause to the skill.
3. Level from the clause: if its first word is a performing verb (coordinated, maintained, prepared, managed, organized, organised, updated, resolved, documented, checked, supported, tracked, handled, processed, scheduled, arranged, ran, wrote, produced, reviewed, led, owned, designed, built, delivered) the signal is `performed`, level 2; otherwise `mentioned`, level 1. **The rules never give level 3.**
4. A declared skill (name + level 1 to 3) that equals a scored skill keeps the worker's level (`source: declared`). A proposed alias maps to its scored skill (`declared_alias`). A name with no scored equivalent is returned in `unmatched` and not scored.
5. A skill both declared and found in text keeps the declared level and gains the quotes as evidence. A skill found only in text is `extracted`, level at most 2.
6. Every quote is re-checked with `quote_is_grounded`; failures are dropped.
7. A declared skill with no quote gets signal `declared_only` and explanation "no supporting example yet".

Measured: across the 8 people, 24 declared skills map to the catalogue; 15 are supported by their one sentence of text, 9 are not; 7 more skills are found only in the text. This is coverage, not accuracy: there is no independent answer key.

### 6.2 Matching (`core.score_role`, `core.rank`)
For each role, `u(s)` = confirmed level (0 if absent); each requirement has importance `i`, required level `r`, `mandatory`.
- `F1 = sum(i * min(1, u/r)) / sum(i)` (skill coverage)
- Gap hours `H = sum(max(0, r - u) * hours_per_level)` over all requirements. `F4 = 1 - min(1, H/120)` (learnability)
- Interests (ordered, `n` of them): interest number `k` (from 0) has weight `n - k`; `F3 = sum(weights of interests found in the role's tags) / sum(all weights)`. **If no interests, F3 is dropped and the other weights are rescaled to sum to 1** (0.60/0.85 and 0.25/0.85). Missing is never zero.
- `score = 0.60*F1 + 0.15*F3 + 0.25*F4`, rounded to 4 decimals.
- Blocking gap: a mandatory requirement with coverage `min(1, u/r)` below 0.5.
- Band: `strong_fit` if F1 >= 0.75 and no blocking gaps; `bridgeable` if F1 >= 0.50 and at most 2 blocking gaps; else `stretch`.
- Order: score descending, then role id ascending.
- Gap priority = `importance * gap_levels * (1.5 if mandatory else 1)`; gaps sorted by priority descending.
- Explanation text: "{Role}: skill coverage {F1 %}. Strongest matches: {up to 3}. Biggest gaps: {up to 2} (~{H} h estimated). Band: {band}. Weights are provisional."

### 6.3 Learning plan (`core.build_plan`)
1. Order gap skills: prerequisites that are also gaps first, then by priority.
2. For each gap skill step from the current level toward the required level. Choose a resource that teaches the skill with `level_from <= current < level_to` and an allowed status. Preference: `verified`, then `seed_unverified`, then `sample_placeholder`; then provider "SAP Learning Hub (student edition)"; then the highest `level_to`; then `resource_id`.
3. Step hours = `(next level - current level) * hours_per_level`.
4. No allowed resource: one step with status `no_verified_resource` for the remaining levels. **Never invent a resource.**
5. `weeks_at_pace = ceil(total hours / weekly_hours)` when weekly hours are given.

### 6.4 Progress and motivation (`engine/motivation.py`)
- Plan percentage = `sum(step hours * step percent / 100) / sum(step hours)`, rounded.
- Event (at most one, in this order): `plan_done`, `step_done`, `halfway` (crossed 50), `welcome_back` (7+ days since last update), `start` (from 0 above 0).
- Message: alternate between the worker's chosen styles by the number of messages already shown. If a style is marked "not helpful" three times in a row and there are two styles, drop it.
- Placeholders available in templates (only these): `total`, `steps_word`, `done`, `percent`, `hours_total`, `hours_left`, `weekly_hours`, `weeks_left`, `matched_count`, `next_step`, `last_step`.
- No streaks, no loss or guilt wording, no comparison with others, nothing about age, years, gender or family. Pause always available.

### 6.6 Fairness comparison (`core.compare`, `core.flags_for`)
Six variants add one sentence to the worker's text: "I am 29 / 42 / 50 / 58 years old." (A29, A42, A50, A58) and "I have 5 / 25 years of experience." (P5, P25). Metrics against the baseline: `skills_jaccard` (overlap of (skill, level) pairs), `top3_overlap`, `kendall_tau` (agreement of the full 8-role order), `max_abs_score_delta`, `plan_hours_delta` (gap hours for the goal role), `lexicon_hits`. Flag a metric that breaches its threshold. A deliberately biased **canary** (levels 2 and 3 lowered by one, plus age-coded words) must be flagged. In rules mode the real variants pass by construction; the audit is a safety net until a language model is used.

4. After any change to aliases or the extractor, run `python data/run_v2_examples.py` and read what changed for all 8 people.
